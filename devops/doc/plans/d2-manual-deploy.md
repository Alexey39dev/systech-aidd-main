# План Спринта D2 - Развертывание на сервер

## Обзор

Развернуть систему на production сервере 89.223.67.136 с использованием готовых Docker образов из GitHub Container Registry. Создать детальную инструкцию для ручного развертывания и выполнить все шаги.

## Основные файлы для работы

- `docker-compose.prod.yml` - конфигурация для production
- `docs/guides/manual-deploy.md` - инструкция по развертыванию (создать)
- `.env.production` - шаблон переменных окружения (создать)

## Этапы реализации

### 1. Создать шаблон .env.production

Создать файл `.env.production` с:

- Всеми необходимыми переменными окружения
- Комментариями с описанием каждой переменной
- Примерами значений для production
- Секретами: `OPENROUTER_API_KEY`, `POSTGRES_PASSWORD`, `TELEGRAM_BOT_TOKEN`
- Настройками БД: `DATABASE_URL` с production параметрами
- Настройками API/Frontend: порты 8002, 3002
- Настройками логирования для production

### 2. Создать скрипт deploy-check.sh

Создать bash-скрипт для автоматической проверки готовности к деплою:

- Проверка наличия SSH ключа `systech_admin_key`
- Проверка наличия файлов `.env` и `docker-compose.prod.yml`
- Проверка SSH доступа к серверу `systech@89.223.67.136`
- Проверка наличия Docker на сервере (`docker --version`, `docker compose version`)
- Проверка свободности портов 8002 и 3002 на сервере
- Проверка прав на создание директории `/opt/systech/dolgachev`
- Вывод итогового отчета: готов ли сервер к развертыванию

### 3. Обновить docker-compose.prod.yml

Адаптировать существующий `docker-compose.prod.yml`:

- Изменить префикс образов на `ghcr.io/dolgachev/` (bot, api, frontend)
- Изменить порты на production значения: API 8002, Frontend 3002
- Убрать pgadmin (не нужен в production)
- Добавить health checks для всех сервисов
- Настроить restart политику: `restart: always`
- Использовать именованный volume для postgres
- Настроить сеть для изоляции сервисов

### 4. Создать инструкцию docs/guides/manual-deploy.md

Подробная пошаговая инструкция на русском языке:

**Раздел 1: Подготовка (локально)**

- Проверка наличия SSH ключа `systech_admin_key`
- Создание файла `.env` на основе `.env.production`
- Заполнение всех секретов и токенов
- Проверка `docker-compose.prod.yml`

**Раздел 2: Подключение к серверу**

- SSH подключение с использованием ключа: `ssh -i systech_admin_key systech@89.223.67.136`
- Проверка установки Docker: `docker --version`, `docker compose version`
- Создание рабочей директории: `/opt/systech/dolgachev`
- Настройка прав доступа

**Раздел 3: Копирование файлов на сервер**

- Копирование `docker-compose.prod.yml` через scp
- Копирование `.env` через scp
- Копирование директории `prompts/` (если требуется кастомный промпт)
- Проверка скопированных файлов

**Раздел 4: Загрузка Docker образов**

- Pull образов из ghcr.io (публичные, без авторизации):
- `docker pull ghcr.io/dolgachev/bot:latest`
- `docker pull ghcr.io/dolgachev/api:latest`
- `docker pull ghcr.io/dolgachev/frontend:latest`
- Проверка загруженных образов: `docker images`

**Раздел 5: Запуск сервисов**

- Запуск через docker compose: `docker compose -f docker-compose.prod.yml up -d`
- Проверка статуса: `docker compose ps`
- Просмотр логов: `docker compose logs -f`

**Раздел 6: Миграции базы данных**

- Проверка завершения миграций: `docker compose logs migrations`
- Проверка таблиц в БД при необходимости

**Раздел 7: Проверка работоспособности**

- Проверка запущенных контейнеров: `docker compose ps`
- Health check API: `curl http://89.223.67.136:8002/health`
- Проверка API docs: `http://89.223.67.136:8002/docs`
- Проверка Frontend: `http://89.223.67.136:3002`
- Проверка Bot: просмотр логов бота
- Проверка БД: количество записей, таблицы

**Раздел 8: Troubleshooting**

- Распространенные проблемы и решения
- Команды для отладки: логи, статус, перезапуск
- Как остановить сервисы: `docker compose down`
- Как обновить образы: pull + restart

### 5. Выполнить развертывание

Пройти по инструкции из `manual-deploy.md`:

- Подготовить все файлы локально
- Подключиться к серверу через SSH
- Скопировать необходимые файлы
- Загрузить Docker образы
- Запустить все сервисы
- Выполнить миграции
- Проверить работоспособность

### 6. Финальная проверка

Убедиться что:

- Все 4 контейнера запущены (postgres, bot, api, frontend)
- API отвечает на запросы через интернет (порт 8002)
- Frontend доступен через браузер (порт 3002)
- Bot работает и пишет логи
- Миграции БД выполнены успешно
- Health checks проходят успешно
