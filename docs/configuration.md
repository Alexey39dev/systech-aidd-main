# Руководство по конфигурации

Это подробное руководство по настройке LLM-ассистента через файл `.env`.

## 📋 Обязательные параметры

### OPENROUTER_API_KEY
**Обязательный параметр**. API ключ для доступа к OpenRouter.

```env
OPENROUTER_API_KEY=sk-or-v1-xxxxxxxxxxxxxxxxxxxxx
```

**Как получить:**
1. Зарегистрируйтесь на [openrouter.ai](https://openrouter.ai)
2. Перейдите в раздел "Keys"
3. Создайте новый API ключ
4. Скопируйте ключ в `.env` файл

## 🤖 Параметры LLM

### SYSTEM_PROMPT
Системный промпт, определяющий роль и поведение ассистента.

**По умолчанию:** `Ты полезный ассистент. Отвечай на вопросы пользователя дружелюбно и информативно.`

**Примеры:**

```env
# Общий ассистент (по умолчанию)
SYSTEM_PROMPT=Ты полезный ассистент. Отвечай на вопросы пользователя дружелюбно и информативно.

# Python эксперт
SYSTEM_PROMPT=Ты эксперт по Python. Отвечай на вопросы о программировании на Python, предоставляя примеры кода и лучшие практики.

# Технический писатель
SYSTEM_PROMPT=Ты технический писатель. Помогай пользователю создавать понятную и структурированную документацию.

# Переводчик
SYSTEM_PROMPT=Ты профессиональный переводчик с английского на русский. Переводи текст точно и естественно.

# Учитель английского
SYSTEM_PROMPT=Ты учитель английского языка. Помогай пользователю изучать английский, исправляй ошибки и объясняй правила.
```

### MAX_HISTORY
Максимальное количество пар сообщений (user + assistant) для хранения в истории.

**По умолчанию:** `10`  
**Диапазон:** 1-100  
**Фактическая длина списка:** MAX_HISTORY * 2 (user + assistant)

```env
# Минимальная история (для коротких диалогов)
MAX_HISTORY=3

# Стандартная история (по умолчанию)
MAX_HISTORY=10

# Расширенная история (для длинных диалогов)
MAX_HISTORY=30

# Максимальная история (внимание: больше токенов)
MAX_HISTORY=50
```

**Влияние на работу:**
- Больше истории = больше контекста для LLM
- Больше истории = больше токенов = выше стоимость
- Меньше истории = меньше памяти о прошлых сообщениях

### LLM_MODEL
Модель LLM для использования через OpenRouter.

**По умолчанию:** `openai/gpt-3.5-turbo`

**Популярные модели:**

```env
# GPT-3.5 Turbo (быстрая и дешевая)
LLM_MODEL=openai/gpt-3.5-turbo

# GPT-4 (более умная, но дорогая)
LLM_MODEL=openai/gpt-4

# GPT-4 Turbo (баланс цены/качества)
LLM_MODEL=openai/gpt-4-turbo

# Claude 3 Sonnet (хороший выбор)
LLM_MODEL=anthropic/claude-3-sonnet

# Claude 3.5 Sonnet (лучшая модель на данный момент)
LLM_MODEL=anthropic/claude-3.5-sonnet

# Бесплатные модели (для тестирования)
LLM_MODEL=openai/gpt-3.5-turbo-instruct
LLM_MODEL=mistralai/mistral-7b-instruct:free
```

**Как выбрать:**
- Для разработки и тестов: бесплатные модели
- Для повседневного использования: GPT-3.5-turbo или Claude 3 Haiku
- Для сложных задач: GPT-4 или Claude 3.5 Sonnet

### LLM_TEMPERATURE
Температура генерации (креативность ответов).

**По умолчанию:** `0.7`  
**Диапазон:** 0.0-2.0

```env
# Детерминированные ответы (факты, код)
LLM_TEMPERATURE=0.0

# Сбалансированные ответы (по умолчанию)
LLM_TEMPERATURE=0.7

# Креативные ответы (истории, идеи)
LLM_TEMPERATURE=1.0

# Очень креативные (экспериментальные)
LLM_TEMPERATURE=1.5
```

**Рекомендации:**
- 0.0-0.3: Программирование, технические ответы
- 0.5-0.8: Общие диалоги, обучение
- 0.9-1.5: Креативное письмо, мозговой штурм

### LLM_MAX_TOKENS
Максимальное количество токенов в ответе LLM.

**По умолчанию:** `1000`  
**Диапазон:** 100-4000

```env
# Короткие ответы
LLM_MAX_TOKENS=300

# Стандартные ответы (по умолчанию)
LLM_MAX_TOKENS=1000

# Длинные ответы
LLM_MAX_TOKENS=2000

# Очень длинные ответы (статьи)
LLM_MAX_TOKENS=4000
```

**Влияние:**
- Больше токенов = дороже запрос
- Больше токенов = дольше ответ
- Меньше токенов = риск обрезания ответа

## 📝 Параметры логирования

### LOG_LEVEL
Уровень детализации логов.

**По умолчанию:** `INFO`  
**Варианты:** `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`

```env
# Максимум информации (для отладки)
LOG_LEVEL=DEBUG

# Стандартный уровень (по умолчанию)
LOG_LEVEL=INFO

# Только предупреждения и ошибки
LOG_LEVEL=WARNING

# Только ошибки
LOG_LEVEL=ERROR
```

### LOG_TO_FILE
Включить логирование в файл.

**По умолчанию:** `false`

```env
# Отключить логи в файл (по умолчанию)
LOG_TO_FILE=false

# Включить логи в файл
LOG_TO_FILE=true
```

**Когда включать:**
- При отладке проблем
- Для мониторинга в продакшене
- Для анализа производительности

### LOG_FILE_PATH
Путь к файлу логов (если LOG_TO_FILE=true).

**По умолчанию:** `logs/app.log`

```env
# Стандартный путь
LOG_FILE_PATH=logs/app.log

# Альтернативный путь
LOG_FILE_PATH=/var/log/llm-assistant.log

# Windows путь
LOG_FILE_PATH=C:\Logs\assistant.log
```

**Особенности:**
- Автоматическая ротация при 10MB
- Сохраняется 5 резервных копий
- Кодировка: UTF-8

### LOG_COLORFUL
Цветной вывод логов (только для консоли).

**По умолчанию:** `true`

```env
# Цветной вывод (по умолчанию)
LOG_COLORFUL=true

# Без цветов (для CI/CD)
LOG_COLORFUL=false
```

## 🎯 Примеры конфигураций для разных сценариев

## ⚠️ Важные замечания

1. **Безопасность:**
   - Никогда не коммитьте `.env` файл в репозиторий
   - Храните API ключи в безопасном месте
   - Используйте разные ключи для разработки и продакшена

2. **Стоимость:**
   - Следите за использованием токенов
   - Более мощные модели стоят дороже
   - Большая история = больше токенов на запрос

3. **Производительность:**
   - Меньшие модели быстрее отвечают
   - Меньше токенов = быстрее ответ
   - Меньше истории = меньше времени на обработку

4. **Качество:**
   - GPT-4 и Claude 3.5 Sonnet дают лучшие результаты
   - Для специализированных задач настройте system_prompt
   - Экспериментируйте с температурой для нужной креативности

## 🔄 Применение изменений

После изменения `.env` файла:

1. Перезапустите приложение:
   ```bash
   make run
   ```

2. Или через PowerShell:
   ```powershell
   .\run.ps1
   ```

Изменения применяются только при запуске приложения.
